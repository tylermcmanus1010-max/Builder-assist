# Builder Assist OpenTakeoff connector

An authenticated, session-based HTTP connection to OpenTakeoff's measurement engine. The server uses `opentakeoff-mcp` **0.9.83** and MCP SDK **1.30.0**, with a committed lockfile. Each initialized MCP session receives its own engine instance and private temporary upload/export directories.

This directory is independent of the Builder Assist site. It has been tested locally over HTTP and includes a [Cloudflare hosting package](cloudflare/README.md). Runtime secrets must be configured separately before hosting.

## Run locally

Requires Node.js 24 or newer. Install with `npm ci`, supply `CONNECTOR_TOKEN` through the process environment, and run `npm start`. Use a randomly generated token of at least 32 bytes, kept in your secret manager. `.env.example` documents settings; the server reads process environment variables and does not automatically load a `.env` file.

The default address is `127.0.0.1:8080`. `npm test` starts temporary servers on loopback, creates synthetic plans, exercises real MCP HTTP requests, and removes its temporary files.

## HTTP contract

All routes except `/healthz` require `Authorization: Bearer <CONNECTOR_TOKEN>`. Every plan/file operation and every MCP request after initialization also requires `Mcp-Session-Id` from the initialize response.

| Method and route | Purpose |
| --- | --- |
| `GET /healthz` | Minimal unauthenticated health response: status, service, version. |
| `POST /mcp` | MCP initialize, initialized notification, tool/resource requests. JSON responses; batch JSON-RPC is disabled. |
| `GET /mcp` | Optional MCP server event stream; one active stream per session. |
| `DELETE /mcp` | Close the session and delete its temporary files. |
| `POST /plans?filename=plan.pdf` | Raw `application/pdf` upload. Response contains `{path:"plan.pdf",bytes,...}`. |
| `POST /files?filename=resume.json` | Raw `application/json` upload of an `opentakeoff.takeoff_canvas.v1` export for `import_takeoff`. |
| `GET /files/report.json` | Download a file previously generated by an export tool in this session. PDF and DXF exports use the same route. |

An app backend should keep one MCP client/session for each active takeoff job:

1. Initialize at `/mcp`, then send `notifications/initialized`.
2. Upload the PDF using that session's ID.
3. Call `load_plan` with `{"path":"plan.pdf"}`.
4. Set the drawing scale, perform measurements, and check the rendered overlay.
5. Call `export_report` with `{"path":"report.json"}` and `export_marked_pdf` with `{"path":"marked.pdf"}`.
6. Download those files and save them to Builder Assist's durable project storage. Close the MCP session when finished.

The app backend must retain the same session across uploads and agent tool calls. An independently initialized OpenAI remote-MCP connection will have a separate engine and cannot automatically see another session's upload. Connect the backend MCP client to the agent's tool loop, or implement an authenticated job-routing layer before using independent remote-MCP clients. Keep the connector's service token on the backend.

Upstream tool schemas describe local disk paths. On this hosted connection, every `path` argument is a **plain filename**. Directory components, absolute paths, URL paths, Windows device names, symlinks, and cross-session file access are rejected. Reads use uploads only; exports write to a separate directory. `export_marked_pdf` with no path writes `export_marked_pdf.pdf`. `export_dxf` with no path writes `export_dxf.dxf`. Report/takeoff exports with no path still return inline JSON. Existing uploads cannot be overwritten. `overwrite:true` is disabled.

`set_scale` correctly returns `confirmed:false`: agent-created scale values still require estimator confirmation. Upstream currently gates `one_click` and `detect_rooms`; this service leaves them disabled and exposes the other 53 tools.

## Hosting requirements

Build the included Dockerfile on a host with Docker/build support. It uses Node 24 on Debian, installs the pinned runtime, runs as the non-root `node` user, and includes a health check. A local Docker build has not been run because Docker is unavailable in this environment.

Configure these settings on the hosted service:

- `CONNECTOR_TOKEN`: a secret created in the host's secret manager.
- `HOST=0.0.0.0`, `PORT=8080` for the included container.
- `ALLOWED_HOSTS`: comma-separated exact hostnames the process will receive, including the chosen public hostname and any proxy-internal hostname. The port is omitted. This must be set for public hosting; defaults only allow localhost.
- `ALLOWED_ORIGINS`: empty for server-to-server access, or a comma-separated list of exact permitted browser origins. Prefer a Builder Assist backend proxy.
- `DATA_DIR`: writable private temporary storage, default `/tmp/opentakeoff`.

Terminate HTTPS at the host/proxy. Route every request for a session to the same running instance; engine state is in memory. Start with one replica and fixed routing. A restart loses open takeoffs; exported reports and marked plans must be copied to durable application storage. `DATA_DIR` contains temporary working files, not a takeoff database. Use per-instance ephemeral storage, so crash leftovers disappear when the instance is replaced. Graceful shutdown and session expiry remove live session directories.

Apply CPU/memory/disk limits at the container host. The engine parses and renders PDFs inside the Node process, so request byte/page limits do not create a process-level sandbox or a hard CPU deadline. A conventional Worker runtime alone cannot execute this Node/native-canvas service; a Node/container host is required. No internet calls are needed by the measurement engine once installed.

## Limits and lifecycle

Defaults are 8 sessions, 30-minute idle expiry, 4-hour maximum session lifetime, 2,000 requests per session, 32 MiB per upload, 128 MiB of files per session, 40 files per session, 200 pages per PDF, and 2 MiB per MCP request. Sessions serialize mutations through a queue capped at four requests. There is one SSE stream per session and a process cap of 128 connections. Idle cleanup runs at most every 30 seconds. All settings except queue/connection caps are documented in `.env.example`.

Uploads are checked before storage. Export storage use is checked before returning a successful MCP result; an oversize export causes a quota error and closes the session. The engine must generate an export before its final size can be measured, so the host's disk quota remains the hard physical limit. Tool arguments, PDF contents, secrets, and host paths are not written to request logs. Responses replace internal session paths with portable filenames.

Session IDs are random UUIDs and namespaced by this service process. The bearer token authenticates Builder Assist as a service, not individual end users; Builder Assist must authorize project access and keep session IDs attached to the correct user/job. Do not place this shared token in browser code.

## Verification

`npm test` passes real HTTP checks for authentication, host/origin restrictions, MCP initialization and 53-tool discovery, upload, native rendering, known 200 sq ft / 60 ft geometry, report and marked-PDF export, all six filesystem tool boundaries, separate session state, concurrent mutations, imported embedded paths, SSE limits, quotas, explicit closure, idle cleanup, and graceful removal of temporary directories.

The pinned upstream `import_takeoff` reads only its supplied uploaded JSON file, merges data into the loaded takeoff, and never changes the loaded document-path map. Embedded source paths/URLs are not opened. Marked-PDF export reopens only document paths previously registered by guarded `load_plan`. The bridge's inventory regression check identifies exactly six tools accepting `path`; review that surface before changing the upstream version.
